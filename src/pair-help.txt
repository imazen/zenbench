Use --wait SECONDS for bounded FIFO admission; the default reports not-run
immediately when another cooperating task owns admission. Ordinary background
load is observed. It is not evidence of clean measurement conditions.
Use zenbench nice -- COMMAND for cooperating background builds/work.

One baseline, one candidate and A/A produce 12 child invocations with four
blocks. This is an invocation count, not a runtime estimate. Every child is
fresh; internal timing vectors stay clustered within that child. Each complete
block contributes one log ratio of arithmetic invocation means. The report
shows geometric mean latency change and between-block log-ratio dispersion.
Iterate reports exploratory estimates; Confirm adds fixed-block intervals.
Positive latency change means slower. A/A is a diagnostic, not a bias correction.

CPU policy remains fail-closed on asymmetric/unknown topology. First inspect
zenbench cpu-info, then use zenbench exec for a verified inherited boundary.
ZENBENCH_CPU_POLICY=unrestricted explicitly permits unverified exploration only.
Commands must stay in the foreground and join workers. Unix programs must not
daemonize or leave their process group. No implicit shell is used.

Metrics and JSON checks default to stdout; set stream="stderr" for diagnostic logs.
Other extractors: tsv (prefix, zero-based column), json (prefix, JSON pointer),
regex (pattern, capture index), wall (explicit only, unit ns, expected 1).
Wall timing includes launch, polling and supervisor cleanup; use internal
metrics for short kernels. Failed extraction never falls back to wall time.
Other correctness contracts: json (prefix, pointers), command (program, args,
timeout_seconds; ${baseline}/${candidate} output directories), or unchecked
with an explicit reason. Correctness runs outside the child's internal metric.

Relative program/cwd/input paths resolve from the plan directory. ${field}
substitution is literal within one argument; spaces do not split arguments.
Same program/different env and different program/same env are both supported.
Only explicit overrides and record_env allowlisted inherited values are retained;
clean_env=true removes inherited state. Binary hashes do not identify shared
libraries or undeclared runtime assets. Declare required assets as case inputs.

Keep full evidence/logs in the ignored attempt directory. Copy only selected.csv
into version control, with a pointer to its packet. Packets include decode,
export and comparison commands. Resume checks identities and retained artifact
hashes; completed cases are reused and incomplete cases get a new full attempt.
Failures and interrupted original attempts remain intact. Never overwrite an
attempt directory. Iterate exit 0 means execution completed only; failures/not-run return 2.

For confirmation: zenbench pair plan.json --mode confirm
Freeze blocks >= 5, aa=true, checked output, and metric.resolution (positive
absolute timing-error bound in the extracted unit before divide_by). Add:
  "confirmation": {"margin_pct":1.0,"control_margin_pct":1.0,
    "family_confidence":0.95,"scope":"inputs-v1","accept":"non_inferiority"}
accept: improvement | equivalence | non_inferiority (default).
Bonferroni-adjusted t intervals use whole-block log ratios; declared timing
error widens endpoints. All planned blocks, verified placement, strict sampled
resources and A/A equivalence are required. Confirm exits 0 for acceptance,
1 for regression, 2 for invalid/inconclusive/incomplete/not-run. No Confirm
resume, outlier trimming, optional stopping or A/A bias subtraction.
Short processes without a complete OS observation remain invalid; use a fixed
longer internal work budget or Iterate. A/A cannot exclude candidate-only bias.
Assumptions: independent approximately normal block log ratios; unchanged work.
Persistent workers and numeric-axis regression fits are not implemented.
