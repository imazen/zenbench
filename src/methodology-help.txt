zenbench methodology guide

CHOOSE THE CLAIM
Iterate is the default: short in-process, randomized serial comparisons for
edit feedback. Exit 0 means execution succeeded; local bootstrap intervals are
exploratory. Confirm uses a fixed fresh-process plan (five processes by default),
process-level intervals and a declared margin. Add --scope to Confirm for a
named study cell; Evidence remains a supported spelling. Neither certifies
publication readiness or fleet coverage.

BUSY WORKSTATIONS
Ordinary load observations do not stall every Iterate round. Keep them enabled
for context; results can guide investigation without authorizing acceptance.
Cooperative FIFO admission and the named-rival scan can still wait.
Use zenbench nice for background work and a shared ZENBENCH_COORDINATION_DIR
for participating accounts. --no-busy-gate is an explicit exploration-only
escape, removing observations required for confirmation.

Keep equivalent work, a small targeted group and nearby A/B samples. Inspect
magnitude, drift and spread. An unstable/small result can remain unresolved.
A/A controls diagnose noise; they do not prove interference affects both arms
equally. SMT, caches, memory bandwidth and package power remain shared even with
a CPU mask. Random order does not make arbitrary background load harmless.

Preserve verified CPU-class placement even for busy iteration. Use cpu-info and
exec --help; unrestricted is an exploratory opt-out, never a confirmation remedy.
Confirm currently requires fresh clean whole-host observations, CPU load <=5%
and zero foreign heavy processes. These conservative checks can reject a useful
CPU partition, and cannot certify continuous quietness on selected cores. Freeze
a candidate before scheduling a confirmation slot; retain unsuccessful attempts.
Do not keep rerunning or adding samples until a desired result appears.

WHAT THE NUMBERS MEAN
The callback defines the timed work. Setup, allocation, teardown, dispatch,
warmup, pooling and input reuse must match the intended application question.
Black-box output does not replace correctness checks or inspecting optimized code.
Warmup does not prove maximum frequency. Observed minimum is not universal speed.

Confirm uses one untrimmed mean per arm per process, then log-ratio Student-t
intervals within a binary or Welch log-latency intervals across saved populations.
Bonferroni covers that comparison family, not all edits/cells in a study.
Independent approximately normal process log values are assumptions, not automatic
guarantees of fresh execution. Many rounds do not create independent processes.
Invalid/inconclusive confirmation is exit 2, confirmed regression is exit 1.

EXTERNAL BINARIES / DIFFERENT ENVIRONMENTS
zenbench pair implements exploratory serial fresh-process A/B with per-arm
environments, timing vectors, correctness checks, A/A and retained failures.
Use zenbench pair --help or zenbench guide --topic pair for a complete plan.
Each invocation remains one process-level observation. External Confirm/Evidence
is not implemented; A/A is a diagnostic, not a calibrated significance rule.

COST AND REPRODUCIBILITY
The retained Linux controls measured Iterate 0.766s and five-process Confirm
3.828s, one invocation each. These are one fixture, excluding compilation and
container launch, not estimates for your workload or a busy fleet. Measure your
actual cells and account for warmup, admission, failed attempts and build time.
Full evidence stays in ignored gzip objects; export selected stable CSV summaries.
Read/reanalyze packets instead of rerunning solely to change presentation.
Executable hashes identify bytes; runtime Git HEAD is not a build manifest.
Retain build flags/toolchain, source state and input identity alongside evidence.
